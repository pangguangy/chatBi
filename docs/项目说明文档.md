- **作品名称**：制造业运营态势 Chat-BI Agent
- **团队名称**：【待填】
- **参赛赛道**：【待填】
- **参赛赛题/方向**：赛题 3 —— 制造业运营态势 Chat-BI Agent（代码开发模式）
- **作品一句话简介**：基于 LangGraph + DeepSeek 的制造业经营数据 Chat-BI Agent，管理者用自然语言直接问数，系统自动完成取数、作图、日报生成与异常溯源，实现「问数即所得、异常可溯源」。

## 二、项目背景与目标

**要解决的问题**：传统制造业经营数据分散在订单、生产计划、生产实绩、质量缺陷、能耗等多张表中，
管理者取数依赖人工写 SQL 或排队找 IT 支持，效率低、门槛高，异常发现往往滞后。

**面向的用户与场景**：面向制造企业的生产、质量、能源、计划等业务管理者，覆盖产量盘点、订单交付、
质量缺陷、能耗监控、班次效率、停线分析等日常经营分析场景。

**目标效果**：让业务人员零 SQL 基础即可自助问数，把「取数 → 制表 → 作图 → 归因」压缩为一句自然语言
提问，并将异常结论与「数据表 + 字段」一一对应，做到可解释、可审计。

**回应赛题要求**：本作品为命题式赛题（赛题 3）。赛题要求覆盖自然语言问数、多表关联、图表生成、
运营日报、异常解释与溯源、任务规划与工具调用、SQL 自动纠错重试等能力，本作品逐项实现（见第三节
能力对照表），并以官方模拟经营数据集为底座、LangGraph 状态机编排多节点工具调用完成闭环。

## 三、核心功能说明

### 主要功能模块（与赛题必选能力对照）

| 赛题必选能力 | 本作品实现 |
|---|---|
| 自然语言问数 | 覆盖产量、订单、质量缺陷、能耗、达成率、延期六类业务问题 |
| 多表关联分析 | dim 维表 + fact 事实表多表 JOIN（车型/产线/客户/计划/实绩/缺陷/能耗） |
| 图表自动生成 | 按问题与结果自动选择柱状图 / 折线图 / 表格 / 文字摘要 |
| 运营日报/月报 | 输入月份一键生成含产量、质量、能耗、延期概览的运营态势日报 |
| 异常解释与溯源 | 对质量、能耗、延期、班次效率、停线五类异常给出数据依据，并写明所用数据表与字段 |
| 任务规划 + 工具调用 | LangGraph 状态机：规划节点 + SQL/图表/异常/报告工具节点 |
| SQL 自动修正重试 | SQL 执行出错时，Agent 依据报错自动修正并重试（上限 3 次） |

### 用户使用流程

1. 在页面输入自然语言问题（或点击示例问题）；
2. Agent 识别意图（普通问数 / 异常归因 / 日报生成）并路由到对应链路；
3. 自动生成并执行 SQL，出错则自动修正重试；
4. 展示 SQL、结果表格、图表、自然语言总结与溯源说明。

### Agent 的关键能力

意图识别、Text-to-SQL、报错驱动 SQL 自我修复、图表类型决策、五类异常检测与溯源、自然语言总结。

### 输入、处理、输出形式

- **输入**：自然语言问题文本。
- **处理**：LangGraph 状态机 → SQLite 查询 → matplotlib 绘图 → 异常检测 → LLM 总结。
- **输出**：执行的 SQL、结果表格、图表（PNG）、日报/回答文本、溯源说明（数据表 + 字段 + 依据 SQL）。

### 典型使用场景示例

「2026年6月各车型总产量是多少？」→ 柱状图 + 排序结果；「哪条产线单车电耗异常升高？」→ 异常溯源
（焊装一线环比 +14.6%、产量仅 +0.7%）；「生成2026年6月运营日报」→ 四板块综合报告。

## 四、实现方式说明

**技术栈**：Python + LangGraph（Agent 状态机）+ Streamlit（前端）+ SQLite（数据）+ DeepSeek API（大模型）。

**使用的大模型**：DeepSeek（`deepseek-chat`，OpenAI 兼容接口，标准库 urllib 调用，无额外 SDK）。

**Agent 编排方式**：LangGraph 有向状态机，节点为规划 / 执行 SQL / SQL 修正 / 图表 / 报告 / 异常溯源 /
汇总，以条件边实现意图分流与重试循环。

**系统流程图**：

```
用户问题
   │
   ▼
[planning]  意图识别(query/report/anomaly) + DeepSeek Text-to-SQL + 图表类型决策
   │
   ├─ 日报/月报 ──► [report] 运行产量/质量/能耗/延期 4 类查询 + 异常检测
   │
   └─ 普通/异常问数
        │
        ▼
   [execute_sql]  执行 SQL（只读校验）
        │ 失败
        ├────► [fix_sql] DeepSeek 依据报错自动修正 SQL ──► 回到 execute_sql（≤3 次重试）
        │ 成功
        ▼
   [chart]       生成柱状图/折线图（或表格/文字）
        │
   [anomaly]     异常溯源（数据表 + 字段依据）
        ▼
   [finalize]   自然语言总结 + 溯源说明
```

**工程结构**：`agent_graph.py`（图编排）、`tools/llm.py`（大模型封装）、`tools/sql_tool.py`（SQL 执行 +
启发式兜底）、`tools/anomaly_tool.py`（异常溯源）、`tools/chart_tool.py`（图表）、`tools/schema.py`
（schema 描述与 Prompt）、`db_init.py`（CSV 导入）、`app.py`（页面）。

## 八、创新点与亮点

- **场景创新**：面向制造业垂直经营分析，把多张事实/维表的取数、绘图、日报、归因整合为一次自然语言问答。
- **交互创新**：输入一句自然语言，输出 SQL、表格、图表、总结与溯源五要素同屏。
- **Agent 编排方式**：LangGraph 状态机 + 条件边，实现「规划 → 执行 → 报错修复 → 图表 → 溯源 → 汇总」闭环。
- **数据处理方式**：SQL 执行加只读校验；内置确定性 SQL 兜底库，LLM 不可用时自动降级。
- **专业知识应用**：内嵌制造业五类异常规则（质量/能耗/延期/班次效率/停线）与环比口径。
- **结果可解释性**：每个异常结论强制附带「数据表 + 字段 + 依据 SQL」溯源。
- **用户体验**：示例问题一键问数，无需学习 SQL。
- **工程实现**：LLM 调用基于标准库 urllib，零额外 SDK 依赖，轻量可移植。
- **可推广价值**：纯 Python 工程，可复用到其它制造企业的经营分析场景。

## 九、应用价值与落地前景

- **降低取数门槛**：管理者零 SQL 基础即可自助问数，缩短决策取数周期。
- **主动发现异常**：质量、能耗、延期、班次效率、停线五类异常自动识别并给出依据。
- **可追溯可信**：结论可回溯到具体数据表与字段，便于验证与治理。
- **目标用户**：制造企业的生产、质量、能源、计划、供应链等经营管理者。
- **效率/成本/质量/体验提升**：取数从「小时级人工 SQL」到「秒级自然语言」，异常发现从被动到主动，
  结论从「只有数字」到「数字 + 依据」，支撑经营态势实时洞察与决策。

## 十、测试与效果说明

- **测试样例**：官方公开问题集 Q_PUB_001~010 与隐藏问题集 Q_HID_001~005，共 15 题（详见
  `docs/测试用例清单.md`）。
- **评测方法**：逐题比对参考答案（产量排序、缺陷率环比、能耗环比、延期归因、夜班效率、停线等），
  校验 SQL 结果与结论一致性。
- **测试结果**：15/15 全部命中参考答案要点；SQL 自动修正重试链路可复现；离线模式下全流程可演示。
- **稳定性/响应**：本地 SQLite 查询为毫秒级；异常溯源为预置确定性 SQL，稳定可复现。
