## 二、作品简介

本作品面向制造业经营分析场景，构建了一个基于大模型的 **Chat-BI Agent**：管理者用**自然语言直接问数**，
系统自动完成「意图识别 → 生成 SQL → 执行查询 → 生成图表 → 异常溯源 → 自然语言总结」的完整闭环，
并支持**一键生成运营日报/月报**。作品以官方模拟制造业经营数据集（订单、生产计划、生产实绩、质量缺陷、
能耗五类事实数据 + 车型/产线/客户三类维表）为数据底座，基于 **LangGraph** 状态机编排多节点任务规划与工具调用，
内嵌 **SQL 自动修正重试**机制与**确定性 SQL 兜底库**，保证大模型不可用或出错时仍能稳定运行，
每个异常结论强制附带「数据表 + 字段」的可解释溯源依据，满足业务审计与信任要求。

## 三、作品背景与意义

传统制造业的经营数据分散在订单、生产计划、实绩、质量、能耗等多张表中，管理者取数依赖人工写 SQL 或
排队找 IT 支持，效率低、门槛高，异常发现往往滞后。本作品针对该痛点，让业务人员**零 SQL 基础即可自助问数**，
把"取数 → 制表 → 作图 → 归因"压缩为一句自然语言提问，实现"问数即所得、异常可溯源"。
同时，通过 LangGraph 的**任务规划 + 工具调用 + 报错驱动自我修复**，探索了大模型在垂直行业数据分析中的
工程化落地范式。

## 四、核心功能

| 必选能力 | 实现说明 |
|---|---|
| 自然语言问数 | 覆盖产量、订单、质量缺陷、能耗、达成率、延期六类业务问题 |
| 多表关联分析 | dim 维表 + fact 事实表多表 JOIN（车型/产线/客户/计划/实绩/缺陷/能耗） |
| 图表自动生成 | 按问题与结果自动选择柱状图 / 折线图 / 表格 / 文字摘要 |
| 运营日报/月报 | 输入月份一键生成含产量、质量、能耗、延期概览的运营态势日报 |
| 异常解释与溯源 | 对质量、能耗、延期、班次效率、停线五类异常给出数据依据，并写明所用数据表与字段 |
| 任务规划 + 工具调用 | LangGraph 状态机：规划节点 + SQL/图表/异常/报告工具节点 |
| SQL 自动修正重试 | SQL 执行出错时，Agent 依据报错自动修正并重试（上限 3 次） |

## 五、技术架构

**技术栈**：Python + LangGraph + Streamlit + SQLite + DeepSeek API（OpenAI 兼容接口，标准库调用）。

**系统流程**：

```
用户问题
   │
   ▼
[planning]  意图识别(query/report/anomaly) + DeepSeek Text-to-SQL + 图表类型决策
   │
   ├─ 日报/月报 ──► [report] 运行产量/质量/能耗/延期 4 类查询 + 异常检测
   │
   └─ 普通/异常问数
        │
        ▼
   [execute_sql]  执行 SQL（只读校验）
        │ 失败
        ├────► [fix_sql] DeepSeek 依据报错自动修正 SQL ──► 回到 execute_sql（≤3 次重试）
        │ 成功
        ▼
   [chart]       生成柱状图/折线图（或表格/文字）
        │
   [anomaly]     异常溯源（数据表 + 字段依据）
        ▼
   [finalize]   自然语言总结 + 溯源说明
```

**模块划分**：

| 模块 | 职责 |
|---|---|
| `agent_graph.py` | LangGraph 状态机：规划/执行/修正/图表/报告/异常/汇总节点 + 条件路由 |
| `tools/llm.py` | DeepSeek API 封装（Text-to-SQL、SQL 修复、自然语言总结） |
| `tools/sql_tool.py` | SQL 执行（只读校验）+ 启发式 SQL 兜底库 + 日报查询 |
| `tools/anomaly_tool.py` | 五类异常检测与溯源（含数据表/字段/SQL 依据） |
| `tools/chart_tool.py` | matplotlib 无界面渲染，色盲友好配色，中文标签 |
| `tools/schema.py` | 数据库 schema 描述 + Prompt 构造 + 溯源字段抽取 |
| `db_init.py` | 读取全部 CSV 导入 SQLite（自动处理编码、跳过 __MACOSX） |
| `app.py` | Streamlit 交互页面（提问/SQL/表格/图表/日报/溯源） |

## 六、关键实现

1. **意图分流**：普通问数、异常归因、日报生成三种意图由 `detect_intent` 识别后路由到不同处理链路。
2. **Text-to-SQL + 兜底**：优先调用 DeepSeek 依据 schema 生成 SQL；无论是否配置密钥，都同步计算一份
   确定性启发式 SQL 作为兜底，LLM 不可用或出错时自动降级，保证演示稳定。
3. **SQL 自动修正重试**：SQL 执行失败时，`fix_sql` 节点把报错信息回传给 DeepSeek 自动修正并重试，
   上限 `MAX_SQL_RETRY = 3`；最后一次切换启发式兜底，形成"LLM 修复 → 确定性兜底"的双层容错。
4. **可解释溯源**：每个异常结论强制附带「现象 / 结论 / 数据依据 / 数据表 / 字段 / 依据 SQL」，
   满足赛题"写明用到哪些数据表、哪些字段"的硬性要求。
5. **离线降级**：未配置密钥时进入离线模式，用内置启发式 SQL + 确定性总结完整跑通全流程。

## 七、创新点

1. **LangGraph 状态机 + 自动修正重试**：将规划、工具调用、报错驱动的 SQL 自我修复组织为闭环，提升 Text-to-SQL 鲁棒性。
2. **确定性 SQL 兜底库**：LLM 不可用或出错时自动降级，保证演示与评审稳定可用。
3. **可解释溯源**：每个异常结论强制附带"数据表 + 字段"依据，满足审计与业务信任需求。
4. **意图分流**：普通问数、异常归因、日报生成三种意图自动路由到不同处理链路。
5. **零额外 SDK 依赖**：LLM 调用基于标准库 urllib，工程更轻量、更易部署。

## 八、应用价值

- **降低取数门槛**：管理者零 SQL 基础即可自助问数，缩短决策取数周期。
- **主动发现异常**：质量、能耗、延期、班次效率、停线五类异常自动识别并给出依据。
- **可追溯可信**：结论可回溯到具体数据表与字段，便于验证与治理。
- **轻量可移植**：纯 Python 工程，本地与 HuggingFace Spaces 均可运行。

## 九、运行与访问方式

1. 安装依赖：`pip install -r requirements.txt`
2. 初始化数据库：`python db_init.py`（读取 CSV 导入 SQLite）
3. （可选）配置密钥：复制 `.env.example` 为 `.env`，填入 `DEEPSEEK_API_KEY`
4. 启动页面：`streamlit run app.py`，浏览器打开 `http://localhost:8501`

> 不配置密钥也可运行：系统自动进入离线模式，完整演示全流程。
